# AI-ML-LLM Stock Prediction - Codebase Audit

## 1. Project Structure Analysis

The project follows a modular architecture centered around a Vietnamese stock trading system (VNstock) with machine learning and LLM integrations.

### Entry Points
- **System Sync**: `scripts/sync_all_data.py` - Orchestrates data ingestion.
- **ML Training**: `scripts/train_ml_tickers.py` - Main training pipeline for LightGBM/XGBoost models.
- **Inference**: `scripts/per_session_predict.py` - Real-time/batch prediction logic.
- **TUI/Dashboard**: `src/ui/dashboard.py` and `web/` - Visual interfaces.

### Core Modules
- **`src/historical/`**: Focuses on fetching historical data (`backdate.py`, `hourly_service.py`).
- **`src/ml/`**: Machine learning logic, including `data_loader.py`, `feature_engineering.py`, and `trainer.py`.
- **`src/llm/`**: Integration with LLM providers (Gemini, OpenAI, Groq, Ollama).
- **`src/streaming/`**: Real-time market data handling (Producers/Consumers).
- **`src/database/`**: SQLAlchemy/AsyncPG connections for TimescaleDB.

### External Integrations
- **Vnstock (v3.0+)**: Main data source via `Vnstock` and `vnstock_data` libraries.
- **TimescaleDB**: High-performance time-series storage.
- **ChromaDB**: Vector database for news/contextual data.

## 2. Technical Audit

### Reusable Components
- **`Settings` (config/settings.py)**: Centralized Pydantic settings for API keys, DB URLs, and ML parameters.
- **`FeatureEngineer` (src/ml/feature_engineering.py)**: Robust technical indicator computation using `pandas-ta`.
- **`DataLoader` (src/ml/data_loader.py)**: Ready-to-use functions for loading OHLCV from DB or Vnstock.
- **Logging/Utils**: Consistent logging style using `structlog`.

### Missing/Incomplete Parts
- **Label Engineering**: Currently use simple threshold-based returns (`trend_threshold_pct`). Could benefit from more sophisticated labels (triple-barrier, etc.).
- **Adapter Layer**: The codebase sometimes mixes Vnstock calls directly into services. A dedicated adapter for the Silver plan (Vnstock Sponsor) would unify data fetching.
- **Daily Report Automation**: There is no dedicated module for generating consolidated PDF/Markdown reports daily.

### Constraints & Precautions
- **Vnstock Version**: Strictly stick to `vnstock>=3.0` API patterns.
- **Database Schema**: TimescaleDB hypertables require Careful timestamp handling (VN Timezone).
- **Model Storage**: Models are stored in `models/<TICKER>/` using `joblib`. Maintain this structure for compatibility with `DualModelTrainer`.
