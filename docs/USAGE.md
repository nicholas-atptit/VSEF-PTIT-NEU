# Usage

This repository is primarily used on Windows for VN market directional benchmark research. The expected project-specific interpreter is:

```powershell
C:\Users\luong\.venv\Scripts\python.exe
```

Use `<repo-approved-venv>\Scripts\python.exe` in documentation or reports when a machine-local path should not be recorded.

## Environment Setup

From the repository root:

```powershell
python -m pip install -r requirements.txt
```

If the dedicated environment already exists, prefer:

```powershell
C:\Users\luong\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Do not commit virtual environments, `.env` files, credentials, tokens, local cache directories, or generated bytecode.

## Validation

Use the PowerShell task runner:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev_tasks.ps1 -Task validate-all
```

If Make is installed:

```powershell
make validate-all
```

Raw validation commands:

```powershell
python scripts/check_repo_hygiene.py
python scripts/check_runtime_preflight.py
C:\Users\luong\.venv\Scripts\python.exe scripts\check_runtime_preflight.py
C:\Users\luong\.venv\Scripts\python.exe scripts\check_provider_usage_policy.py
C:\Users\luong\.venv\Scripts\python.exe -m pytest tests/data/test_provider_usage_policy.py -q
C:\Users\luong\.venv\Scripts\python.exe -m pytest tests/data/test_vn_price_gateway_contract.py -q
C:\Users\luong\.venv\Scripts\python.exe -m pytest tests/ml/test_directional_accuracy_metrics.py -q
```

These commands are safe validation commands. They do not fetch market data, run benchmarks, train models, or generate paper/DOCX artifacts.

## Provider Policy

Normal fetch and benchmark code must use the provider gateway:

- `src/data/providers/vn_price_gateway.py`
- `src/data/providers/vn_provider_contract.py`
- `src/data/adapters/vnstock_adapter.py`

Check policy with:

```powershell
C:\Users\luong\.venv\Scripts\python.exe scripts\check_provider_usage_policy.py
```

Raw `vnstock` or `vnstock_data` imports are allowed only in approved adapters, probes, diagnostics, and tests.

## Data, Cache, And Output Locations

Preserved repository artifacts live under:

- `data/`
- `outputs/`
- `reports/generated/`
- `archive/generated_data_snapshots/`
- `archive/reports_superseded/`

Do not delete market cache, raw fetch data, benchmark outputs, generated reports, or archive snapshots during cleanup.

## Git LFS

Data and generated artifacts are tracked with Git LFS where applicable. After clone or checkout:

```powershell
git lfs install
git lfs pull
```

Before committing large data-like files, confirm `.gitattributes` applies the `lfs` filter. Do not bypass LFS for backup artifacts.

## Tags And Pushes

Tags are disabled by project preference:

```powershell
git push origin HEAD
```

Do not run:

```powershell
git push --tags
git push --mirror
```

## Avoiding Accidental Experiment Runs

- Do not run benchmark scripts without a written protocol.
- Do not run fetch/refetch scripts without a written protocol.
- Do not train models as part of cleanup or documentation.
- Do not generate paper/DOCX artifacts unless explicitly requested.
- Prefer `scripts/dev_tasks.ps1` or `make validate-all` for validation because they contain only safe checks.
